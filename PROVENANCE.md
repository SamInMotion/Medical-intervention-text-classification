## Known limitations

- `scripts/make_paper_artifacts.py` and `bootstrap_paired_permutation.py` expect
  per-fold files without the seed suffix the multi-seed protocol introduced, and
  do not run on this tree. `scripts/make_fig1_gap_forest.py` and
  `scripts/bootstrap_bert_per_fold.py` are the scripts that actually produced
  the reported values and Figure 1, and both run cleanly.
- The `tab:assignment` recovery rate (16%) is not stratified by term class
  (check tag, qualifier, or substantive heading). The manuscript states this
  caveat directly in §4.3.
- `bow_stats_results.json` includes a Nadeau-Bengio corrected-*t* computation
  whose correction factor is stored as 1.0 for all topics rather than the
  correct 5-fold value. This statistic is not used or cited anywhere in the
  manuscript; the file is retained for the raw per-fold values it also
  contains.
- `src/auto_mesh.py` builds the matched-term list from an unsorted Python set,
  so term order in the constructed auto-MeSH text is not guaranteed identical
  across runs. This is one plausible contributor, alongside Keras layer
  initialisation, to the residual run-to-run variance characterised
  empirically in Appendix A.3.

## Notes on `tab:power` vs `tab:design_sensitivity`

These two tables draw on different underlying sessions and should not be
cross-referenced as if they shared a data source: `tab:power`'s per-fold SDs
come from a single-topic session (`bow_stats_results.json`); the canonical
reference row in `tab:design_sensitivity` comes from the seven-rerun
characterisation used throughout the rest of the paper
(`outputs/bow_statins_multirun_summary.json`). Both are reported because both
are relevant to different questions the manuscript asks; neither supersedes
the other.
